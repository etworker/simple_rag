## 一、严重 Bug（确认，建议优先修复）

### 1.【高】qa_engine.py 冲突上下文构建必崩溃（KeyError）

文件：`rag_demo/app/services/qa_engine.py`

`_build_context()` 第 180 行访问了不存在的键：

```python
f"{c['doc_b_file']}称「{c['doc_b_says']}」"
```

而 `_detect_conflicts()`（第 259-274 行）生成的冲突 dict 里，B 侧的字段是 **`doc_others`**（一个列表），并没有 `doc_b_file` / `doc_b_says`：

```python
conflicts.append({
    "point": ...,
    "doc_a_file": ...,
    "doc_a_location": ...,
    "doc_a_says": ...,
    "doc_others": [...],   # ← 实际是 doc_others，不是 doc_b_*
})
```

**后果**：只要检索结果中出现跨文档矛盾（`conflicts` 非空），`ask()` 构建 context 时就会抛 `KeyError`，问答接口返回 500。这恰恰破坏了系统最核心的"矛盾醒目提示"功能——越是有矛盾越会崩。

**修复方向**：`_build_context` 应从 `doc_others` 列表拼接所有 B 侧描述（注意一条矛盾可能对应多个 B）。

## 二、逻辑缺陷（确认，但不影响功能正确性）

### 2.【中】doc_store.py 把 FAISS index 当布尔缓存标志，日志恒误

文件：`rag_demo/app/services/doc_store.py` 第 143-147 行

```python
embeddings, from_cache = self._vector_store.get_or_compute(...)
if from_cache:
    log.info("✅ 复用向量缓存 ...")
else:
    log.info("🆕 新算向量 ...")
```

`version_diff/vectorstore.py` 的 `get_or_compute()` 返回值是 `(embeddings, faiss_index)`——第二个元素**始终是 FAISS index 对象**，不是布尔"是否命中缓存"。因此在 `doc_store.py` 中 `from_cache` 恒为真值，**永远打印"复用向量缓存"**，即使首次计算也如此。

**复核结论**：
- 该缺陷仅造成日志误导，不会导致功能错误（embedding 本身取的是第一个返回值，正确）。
- 其他调用点（`version_diff/engine.py` 第 97、145 行用 `_` 丢弃；`matcher.py` 第 81 行正确当 index 用）都没有误用，仅 `doc_store.py` 一处误用。

**修复方向**：让 `get_or_compute` 返回 `(embeddings, from_cache: bool, index)`，或仅在 `doc_store` 处去掉对该布尔值的依赖。

## 三、安全隐患（建议）

### 3.【中】.env 明文存放真实 API 密钥

文件：`simple_rag/.env`

内含两个真实格式的 AWS Bedrock / OpenAI Bearer Token（`ABSK...`）。**已在 .gitignore 排除、未被 git 跟踪**（已确认），但明文落盘仍是风险：

- 建议改用系统级密钥管理（环境变量注入 / secretsmanager / keyring），不要明文落盘。
- 建议轮换这两把密钥（存在被拷贝/提交泄露的可能）。
- `start.sh` 加载的 `../.secrets.env` 文件名**未被 .gitignore 覆盖**（`.gitignore` 只匹配 `.env`、`.env.*`、`*.key`、`*.pem`，而 `.secrets.env` 不匹配 `.env.*`）。一旦有人创建该文件就可能被提交进仓库。

## 四、一致性问题（确认，低级）

### 4.【低】docstring 中的包名拼写与真实模块不一致

- `doc_parser/src/doc_parser/__init__.py` 示例写 `from docparser import ...`（真实模块为 `doc_parser`）。
- `version_diff/src/version_diff/__init__.py` 示例写 `from versiondiff import ...`（真实模块为 `version_diff`）。

仅文档字符串拼写，不影响运行，但会误导调用者。

### 5.【低】启动脚本 .env 文件名约定不一致

- `start.bat`（Windows）加载 `..\.env`。
- `start.sh`（Linux/Mac）加载 `../.secrets.env`。
- `main.py` 的 `_load_secrets()` 依次查找 `.env` / `secrets.env`。

三个入口对密钥文件的命名/路径约定不一致，容易漏加载。建议统一。

---

## 五、设计脆弱性（建议，非 bug）

### 6.【低】WebSocketLogHandler 使用类级可变属性

文件：`rag_demo/app/main.py` 第 176-178 行

```python
class WebSocketLogHandler(logging.Handler):
    clients: list = []
    history: list = []
```

`clients`、`history` 为类属性（所有实例共享），在 uvicorn 多进程 / 多 worker 或 `--reload` 场景下日志推送可能错乱。当前单进程下可用，属设计上的脆弱点。
