# doc_parser 设计文档

> 通用文档解析库 — PDF/Word → 结构化段落 + 表格

---

## 1. 设计目标

把企业常见格式的管理制度文档（PDF / Word）解析为**带定位信息的结构化数据**，为下游的向量检索、版本对比、冲突检测提供高质量输入。

核心难点与解法：

| 难点 | 解法 |
|------|------|
| 页眉/页脚/水印噪声 | 按页面坐标百分比界定页眉页脚区域，区域内的文字行自动过滤 |
| 表格文字混入正文流 | 第一遍提取表格区域坐标，第二遍拼正文时排除这些区域 |
| 跨页段落截断 | 不按页分段，而是把全文拼接成一条流，再按语义信号（空行/章节标题/句末终止符）分段 |
| 页眉页脚重复污染 | 统计每行在全文中的出现次数，超过阈值的行判定为页眉/页脚并过滤 |
| 跨页表格被截断为多个 | 启发式合并：同文件 + 页码连续 + 列数接近 + 重复表头 → 合并为一个 `Table`，跳过重复表头行 |
| 左侧 margin 编号列 | 部分 PDF 将章节编号放在左侧 margin 区域，按 x 坐标分离编号列并拼接到正文行首 |
| 空白模板表格 | 空单元格率超过阈值的表格（签到表/申请表）自动过滤 |
| 版本管理元数据行 | 修订日期/版次/版本号等独立成行的元数据，通过正则匹配从段落流中剥离 |

## 3. 数据模型

解析结果统一为 `Document` 对象，包含 `paragraphs`（段落列表）和 `tables`（表格列表）。
每个段落和表格都携带**定位信息**（页码、章节号、章节标题）和**来源信息**（源文件名、原始块顺序）。

### 3.1 Paragraph

```python
@dataclass
class Paragraph:
    text: str  # 段落正文
    page: int = 0  # 起始页码（Word 统一为 0）
    page_end: int = 0  # 结束页码（跨页段落时 > page）
    chapter: str = ""  # 章节号，如 "2.3"
    chapter_title: str = ""  # 章节标题，如 "备份策略"
    source_file: str = ""  # 来源文件名
    index: int = 0  # 段落序号（在同文档段落列表中的位置）
    order: int = 0  # 文档内原始块顺序（用于与表格交错渲染）
```

- `location` 只读属性：格式如 `第3-4页 / §2.3 / 备份策略`
- `to_dict()` / `from_dict()`：JSON 序列化/反序列化
- `to_markdown()`：转为 Markdown 片段（有章节号则渲染为标题）

### 3.2 Table

```python
@dataclass
class Table:
    rows: list  # 二维数组 list[list[str]]，每行一个字符串列表
    headers: list = []  # 表头（可选，为空时用 rows[0] 作表头）
    page: int = 0  # 起始页码
    page_end: int = 0  # 结束页码（跨页表格时 > page）
    chapter: str = ""  # 所属章节号
    chapter_title: str = ""  # 所属章节标题
    context_before: str = ""  # 表格前一段正文（上下文，用于理解表格含义）
    source_file: str = ""  # 来源文件名
    index: int = 0  # 表格序号
    order: int = 0  # 文档内原始块顺序
```

- `location` 只读属性：格式如 `第3-4页 / §2.1 / 风险应对`
- `to_markdown()`：转为 Markdown 表格语法

### 3.3 Document

```python
@dataclass
class Document:
    filename: str                # 源文件名
    paragraphs: list[Paragraph]  # 段落列表
    tables: list[Table]          # 表格列表

    def to_dict(self) -> dict             # 序列化为 JSON 友好的 dict
    def to_markdown(self) -> str          # 转为 Markdown（段落和表格按原始顺序交错）
    @classmethod
    def from_dict(cls, d) -> Document     # 从 dict 反序列化
```

`to_markdown()` 排序策略：
- 优先使用 `order` 字段（解析器提供的原始块顺序）
- `order=0`（旧数据）回退到 `index`
- 章节标题自动渲染为 `#` / `##` / `###`（层级按编号深度推断）
- 目录条目（末尾有页码引用）自动跳过

## 4. PDF 解析流程（`extract_pdf`）

采用**单次打开 PDF、两遍遍历**策略：

### 第一遍：收集 + 提取表格

```
for each page:
    1. 提取表格（pdfplumber.extract_tables）+ 记算表格区域坐标
    2. 收集所有文字行（words → lines，按 y 坐标聚合）
    3. 过滤页眉/页脚区域内的行（top < page_height * header_margin_pct% 或 bottom > page_height * (100 - footer_margin_pct)%）
    4. 分离左侧 margin 编号列（x < margin_number_x 且匹配编号正则的 word）
```

统计所有行在全文中的出现频率，出现次数超过 `repeat_line_threshold_pct%` 的行判定为页眉/页脚重复行。

### 第二遍：拼接正文流 + 语义分段

```
for each page:
    排除表格区域和重复行后的文字行
    → 拼接到全文流（带页码边界信息）

在全文流上调用 _split_stream 分段：
    分割信号（优先级从高到低）：
    1. 章节标题行前断开
    2. 连续空行
    3. 句末终止符 + 段落已达一定长度（>= sentence_break_min_length）
    4. 长度上限强制断开（>= max_paragraph_length）

分段后通过 _find_page 反查每段对应的页码
```

### 后处理

```
_filter_template_tables    # 过滤空白模板表格
_merge_cross_page_tables   # 合并跨页连续表格
_assign_table_chapters     # 为表格分配最近的章节信息
```

## 5. Word 解析流程（`extract_docx`）

使用 `python-docx`，通过 `_iter_docx_blocks` 按 OOXML body 顺序交替遍历段落和表格：

```python
def _iter_docx_blocks(doc):
    for child in doc.element.body.iterchildren():
        if isinstance(child, CT_P):
            yield "paragraph", DocxParagraph(child, doc)
        elif isinstance(child, CT_Tbl):
            yield "table", DocxTable(child, doc)
```

**关键设计：按 body 块顺序遍历**，而非分别遍历 `doc.paragraphs` 和 `doc.tables`。
后者会让所有表格错误地继承最后一个章节号，因为章节检测是在段落遍历时推进的。

- **段落**：过滤空文本 → 先检测章节标题（短标题免长度过滤）→ 构建 `Paragraph`
- **表格**：`row.cells` 提取文本 → `_clean_table` 清理空行空列 → 构建 `Table`
- **`order` 字段**：记录每个块在文档中的原始位置，用于 `to_markdown()` 交错渲染
- **后处理**：与 PDF 路径一致的 `_filter_template_tables` + `_assign_table_chapters`

Word 文档无页码概念，`page` 字段统一为 0。

## 6. 跨页表格合并（`_merge_cross_page_tables`）

启发式合并条件（同时满足）：

1. 同一 `source_file`
2. 页码连续（后续表格的 `page` == 前一表格的 `page_end` + 1）
3. 列数接近（差异 ≤ 1）
4. 首行（表头）Token Jaccard 相似度 ≥ 0.85

合并后：
- 保留首张表格的 `headers` / `page` / `chapter`
- 续页的数据行追加到首张的 `rows` 末尾
- 续页第 0 行若与表头 Token Jaccard 相似度 ≥ 0.85 → 跳过（重复表头）
- 列数对齐：短的补空，长的截断
- 更新 `page_end` = 末页页码

## 7. 章节检测（`_detect_chapter`）

通过正则匹配识别章节标题。默认模式：

| 模式 | 匹配示例 |
|------|----------|
| `^(\d+\.\d+\.\d+)\s+(.+)` | `1.2.3 安全管理要求` |
| `^(\d+\.\d+)\s+(.+)` | `2.3 备份策略` |
| `^(\d+)\s+(.+)` | `3 总则` |
| `^第\s*(\d+)\s*[章节]\s*(.+)` | `第3章 运维管理` |

约束：文本长度超过 `max_chapter_title_length`（默认 80）的不视为标题。

---

## 8. 元数据行剥离（`noise_line_patterns`）

独立成行的版本管理元数据（如"修订日期：2026-05-08"）会被从段落流中剥离，避免被并入相邻正文造成句子拼接。默认匹配模式：

```
^修订日期\s*[：:]\s*\S+$
^发布日期\s*[：:]\s*\S+$
^修订时间\s*[：:]\s*\S+$
^\d{4}[-./]\s*\d{1,2}[-./]\s*\d{1,2}$
^版\s*次\s*[：:]\s*\S+$
^版本号\s*[：:]\s*\S+$
^(?:R\d{2,}|版本\s*\S+)\s*$
^修订次数\s*[：:]\s*\d+\s+\S+\s+页码
修订日期\s*[：:]\s*\d{4}-\d{1,2}-\d{1,2}\s*$
```

所有模式均可通过 `config['extract']['noise_line_patterns']` 覆盖。

---

## 9. 智能后端选择（`backend: "auto"`）

`auto` 模式先对 PDF 做快速预扫描（采样前 5 页，< 1s），根据文档特征自动选择后端：

| 检测项 | 条件 | 选择 | 理由 |
|--------|------|------|------|
| 扫描件 | 平均文字 < 50 字/页 | MinerU | 需要 OCR |
| 扫描件 | 大图片覆盖 > 50% 页面 | MinerU | 图片型 PDF |
| 无框线表格 | 有绘图对象但 pdfplumber 提取不到表格 | MinerU | 表格被漏掉 |
| 无框线表格 | 文本含表头关键词 + 列对齐特征 | MinerU | 疑似表格 |
| 正常文档 | pdfplumber 表格提取正常 | pdfplumber | 速度快 |

若 MinerU 未安装，自动降级到 pdfplumber。

## 10. 配置项

| 配置键 | 默认值 | 说明 |
|--------|--------|------|
| `header_margin_pct` | 8 | 页眉区域占页面高度的百分比 |
| `footer_margin_pct` | 8 | 页脚区域占页面高度的百分比 |
| `repeat_line_threshold_pct` | 30 | 行在全文出现次数超过此百分比 → 判为页眉/页脚 |
| `min_paragraph_length` | 10 | 段落最小字符数，短于此值的丢弃 |
| `max_paragraph_length` | 600 | 段落最大字符数，超长时强制断开 |
| `max_chapter_title_length` | 80 | 章节标题最大长度 |
| `sentence_break_min_length` | 40 | 句末断句的最小段落长度 |
| `chapter_patterns` | (见上文) | 章节标题正则列表 |
| `noise_line_patterns` | (见上文) | 元数据行剥离正则列表 |
| `margin_number_x` | 130 | 左侧编号列的 x 坐标阈值（0 = 禁用） |
| `margin_number_pattern` | `^(?:\d+(?:\.\d+)*\|[A-Z])$` | 编号列中 word 的匹配正则 |
| `table_empty_cell_threshold` | 0.6 | 空单元格率超过此值的表格过滤（1.0 = 禁用） |
| `table_empty_placeholders` | `["□", "☐", "○", "——"]` | 视为空单元格的占位符 |
| `backend` | `"pdfplumber"` | PDF 解析后端：`"pdfplumber"` / `"mineru"` / `"auto"` |
| `mineru_backend` | `"auto"` | MinerU 引擎：`"vlm"`(GPU) / `"pipeline"`(CPU) / `"auto"`(自动检测) |
| `mineru_output_dir` | `""` | MinerU 输出目录（空=临时目录） |
| `mineru_timeout` | `600` | MinerU 解析超时秒数 |

配置传入方式：`parse(filepath, config={"extract": {...}})`，与默认配置深拷贝后合并。
