> 面向部署者与最终用户 ｜ 代码状态：2026-08 全量重构后

---

## 1. 环境要求

- Python 3.10+（推荐），`uv` 包管理器（https://docs.astral.sh/uv/）
- 操作系统：Linux / macOS / Windows
- 联网：首次需下载 Embedding 模型权重（或提前放入 HF 缓存）；之后可完全离线
- LLM：至少配置一种后端凭证
  - Bedrock：`AWS_BEARER_TOKEN_BEDROCK`（环境变量）
  - OpenAI 兼容（含本地 GLM / DeepSeek）：`OPENAI_API_KEY` 或 `DEEPSEEK_API_KEY` 等
- 深度学习后端（可选）：docling / mineru 需 torch；`scripts/install_system.py` 会自动按 GPU 情况安装 CUDA 版或 CPU 版 torch（无 GPU 也能跑 mineru pipeline 模式，仅速度较慢）

## 2. 安装与配置

### 2.1 克隆与依赖同步

```bash
git clone <repo> && cd simple_rag
# 一键安装全部依赖（推荐）：自动检测 GPU → 装匹配 torch → uv sync --all-extras
# 默认走清华 PyPI 镜像（AWS 宁夏/国内网络友好）；可用 --pypi-index/--torch-index 覆盖
python scripts/install_system.py
# 无系统 Python 时（uv 自动下载托管 Python）：
# uv run --no-project python scripts/install_system.py
# 换阿里云 PyPI 镜像：python scripts/install_system.py --pypi-index https://mirrors.aliyun.com/pypi/simple
# 仅同步不装 torch：python scripts/install_system.py --sync-only

# 或仅同步某个模块（uv workspace 自动解析三个兄弟包）：
uv sync --project rag_demo
```

> **GPU 说明**：GPU 环境安装后即含 CUDA 版 torch（torch.cuda.is_available()=True）、faiss-gpu 与
> onnxruntime-gpu（embedding 推理走 CUDAExecutionProvider）。验证：
> `.venv/bin/python -c "import torch,faiss,onnxruntime as o; print(torch.cuda.is_available(), faiss.get_num_gpus(), o.get_available_providers())"`

### 2.2 配置 .env（LLM / 环境变量）

项目根目录已有 `.env` 示例。关键变量：

> ⚠️ `.env` 请使用 **LF 行尾**（Linux/macOS 编辑或 `sed -i 's/\r$//' .env` 转换）。
> Windows 编辑产生的 CRLF 行尾虽被 `main.py`/`start.sh` 兼容（后者会先去除 `\r`），
> 但直接 `source .env` 时会报 `$'\r': command not found` 且 Bearer token 尾带 `\r` 导致请求失败。

```bash
# Bedrock（默认后端）
AWS_BEARER_TOKEN_BEDROCK=****            # 必填（如使用 bedrock 后端）
AWS_REGION=us-east-1

# OpenAI 兼容（本地 GLM / DeepSeek 等，可选）
OPENAI_API_KEY=****
DEEPSEEK_API_KEY=****

# 离线模式（避免 HuggingFace 联网）
HF_HUB_OFFLINE=1
TRANSFORMERS_OFFLINE=1

# 可选覆盖（LLM 后端/模型/区域）
LLM_BACKEND=bedrock                    # 或 openai
LLM_MODEL=zai.glm-4.7-flash
LLM_BASE_URL=                          # OpenAI 兼容后端的 base_url
AWS_REGION=us-east-1
# Embedding 相关（默认基于 fastembed / ONNX，零 torch 依赖）
EMBEDDING_MODEL=BAAI/bge-small-zh-v1.5  # 覆盖 embedding.model（config.json 显式设置时优先）
SIMPLE_RAG_EMBEDDING_DTYPE=auto        # auto / float16 / bfloat16 / float32（覆盖 embedding.dtype）
SIMPLE_RAG_EMBEDDING_DEVICE=auto       # auto / cpu / cuda / mps（优先级高于 config.json 的 embedding.device）
```

### 2.3 配置 config.json（运行参数）

`rag_demo/config.json` **不入库**，新环境复制示例后修改：

```bash
cp rag_demo/config.example.json rag_demo/config.json
```

主要字段（详见 `docs/设计文档.md` 第 8 节）：

```jsonc
{
  "llm_profiles": {
    "self_hosted_glm": { "provider": "openai", "model": "...", "base_url": "...", "api_key": "..." },
    "bedrock_glm_flash": { "provider": "bedrock", "model": "zai.glm-4.7-flash", "api_key_env": "AWS_BEARER_TOKEN_BEDROCK" }
  },
  "llm_routing": { "qa": "bedrock_glm_flash", "pre_review": "bedrock_glm_flash", "conflict_detection": "bedrock_glm_flash" },
  "embedding": { "model": "jinaai/jina-embeddings-v2-base-zh", "device": "auto" },
  "retrieval": { "top_k": 15, "similarity_threshold": 0.5 },
  "pre_review": {
    "similarity_threshold": 0.8,
    "batch_size": 0,
    "parse_backend": "pdfplumber",   // PDF 解析后端: pdfplumber(默认,文本型文档最稳) / auto / pymupdf / docling / mineru
    "docling_device": "cuda",        // docling 推理设备: auto/cuda/cpu
    "docling_batch_size": 0          // docling 推理 batch: 0=默认4, 16-32 提升 GPU 利用率
  },
  "conflict_detection": { "min_score": 0.7, "min_similarity": 0.5, "max_similarity": 0.95 },
  "judge": { "prompt_file": "", "prompt_template": "" }
}
```

> **解析后端选型**（详见 docs/PDF解析库实测报告.md）：默认 **pdfplumber**——对文本型制度文档段落切分最稳（实测 R3-2→R3-3 找到真实修改、无碎句）；
> **docling** 用于无框线表格/复杂版面场景（表格 TEDS 开源最强，但布局模型偶把标题行插入段落造成碎句）；
> **pymupdf** 快路径（秒级）、**mineru** 中文扫描件 OCR。auto 智能路由：扫描件→mineru、无框线表格→docling、普通→pymupdf。

> 提示：修改 `llm_routing` 可让不同环节走不同模型（如问答用快模型、预审核用强思考模型）。

> ⚠️ 提示：**切换 `embedding.model`（向量模型）会使已入库文档的向量全部失效**（向量维度/分布改变），必须**重置知识库**（设置页保存时若检测到模型变更会弹窗提醒；保存后请手动"重置知识库"再重新上传文档），否则检索会维度不匹配或结果失真。

## 3. 启动服务

### 3.1 一键启动（推荐）

```bash
# Linux / macOS
./start.sh
# Windows
start.bat
```

脚本会：`uv sync` → 加载 `.env` → 设置离线环境变量 → 启动 Uvicorn。

### 3.2 手动启动

```bash
cd rag_demo
export HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1
# 同时把 .env 中的变量 export 到当前 shell
uv run uvicorn app.main:app --host 0.0.0.0 --port 8000
```

启动后访问：
- Web UI：http://localhost:8000
- 交互式 API 文档：http://localhost:8000/docs

## 4. Web UI 使用流程

### 4.1 上传与预审核
1. 在"上传"页选择文档（PDF / `.docx`，旧版 `.doc` 需先转换为 `.docx`）。
2. 若库中已存在**同名不同内容**文档，会询问：
   - **覆盖已有文档**：旧版留存用于版本对比。
   - **作为新版本并存**：旧版保留，新文档做版本对比。
3. 上传后自动进入预审核，页面通过 SSE 实时显示进度（解析 → 嵌入 → 检索 → 差异 → 判定）。
4. 完成后展示：
   - **跨文档矛盾**（来自 `pre_review`）
   - **版本变更**（若为新版本，来自 `version_compare`）
5. 管理员**确认入库**或**拒绝**。

### 4.2 问答
1. 进入问答页，输入问题。
2. 答案附带来源引用 `[1][2]`；若检索内容存在跨文档矛盾，会显示 ⚠️ 冲突提示。
3. 支持多轮对话、历史查看、会话重置/删除。

### 4.3 文档管理
- 文档列表、PDF 预览、页面 PNG 预览、段落文本预览。
- 删除单篇文档；"清空知识库"会删除所有文档与缓存，从 0 开始（谨慎）。

## 5. 命令行 / 脚本化调用

除了 Web，差异引擎可作为纯 Python 库或示例脚本使用。

### 5.1 用示例脚本验证版本差异 + LLM 归纳

```bash
cd version_diff
uv run python examples/verify_version_diff.py <旧版.pdf> <新版.pdf> --model zai.glm-4.7-flash
# 不传路径时默认使用 data/pdf 下的 IT运维管理规范 v1/v2
```

脚本会：解析两版 → `DiffEngine.version_compare` → 用 `ask_once` 把差异归纳成结构化中文摘要，输出写入 `<repo>/temp/verify_version_diff_output.txt`。

## 6. 常见问题排查

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 启动报 `未找到 uv` | 未安装 uv | 按 https://docs.astral.sh/uv/ 安装 |
| 问答返回 503 `LLM 服务不可用` | API Key 未配置 / 后端不可达 | 检查 `.env` 中对应 `api_key_env` 变量；确认 `llm_routing` 指向的 profile 已配 |
| 解析结果为空 / 段落极少 | 上传的是纯图片扫描 PDF（无文本层） | 默认后端 pdfplumber 无 OCR；改用 MinerU 后端（`backend: "mineru"`，需已安装）可解析扫描件 |
| Embedding 很慢 | 在用 CPU 且文档很大 | 配置 `embedding.device` 为 `cuda`；或复用向量缓存避免重复计算 |
| HuggingFace 联网失败 | 离线环境未设变量 | 设置 `HF_HUB_OFFLINE=1`、`TRANSFORMERS_OFFLINE=1` 并确保模型已缓存 |
| 预审核进度卡住 | 大文档 + CPU embedding | 属正常耗时，观察日志；可在 `config.json` 调低 `pre_review.similarity_threshold` 减少候选 |
| 冲突检测无结果 | 检索段落均来自同一文档 | `detect_conflicts` 仅对**跨文档**段落对生效 |
| mineru 后端报缺依赖 | 未安装 mineru extra | 运行 `python scripts/install_system.py`（含 mineru[pipeline,vlm]）；无 GPU 会自动用 pipeline 模式 |

## 7. 数据目录

默认根：`~/.simple_rag/`（可在 `config.json` 的 `cache.base_dir` 修改）

```
uploads/        上传文件（SHA256 命名）
doc_store/      已入库文档元数据 + 段落 + 向量索引（FAISS 持久化）
parse_cache/    解析结果缓存
vector_cache/   Embedding 向量缓存
page_cache/     PDF 页面 PNG 缓存
review_cache/   预审核任务状态与结果缓存
chat_history/   问答会话历史
logs/           运行日志（app.log）
```

> 注：`doc_store/`、`chat_history/` 由 `ConfigStore`/`main.py` 在 `~/.simple_rag/` 下自动创建；"清空知识库"（`/api/documents/clear`）会清空文档、解析/向量/页面/预审核缓存，但**不删除** `chat_history/` 与 `logs/`。
