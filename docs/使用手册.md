# 使用手册（User / Operations Guide）

> 面向部署者与最终用户 ｜ 代码状态：2026-08 全量重构后

---

## 1. 环境要求

- Python 3.10+（推荐），`uv` 包管理器（https://docs.astral.sh/uv/）
- 操作系统：Linux / macOS / Windows
- 联网：首次需下载 Embedding 模型权重（或提前放入 HF 缓存）；之后可完全离线
- LLM：至少配置一种后端凭证
  - Bedrock：`AWS_BEARER_TOKEN_BEDROCK`（环境变量）
  - OpenAI 兼容（含本地 GLM / DeepSeek）：`OPENAI_API_KEY` 或 `DEEPSEEK_API_KEY` 等
- 深度学习后端（可选）：docling / mineru 需 torch；`setup_env.py` 会自动按 GPU 情况安装 CUDA 版或 CPU 版 torch（无 GPU 也能跑 mineru pipeline 模式，仅速度较慢）

> **部署硬件选择**：快速原型阶段不要求 GPU，单台普通 CPU 机器即可运行解析、Embedding、版本审核和 RAG 问答；如果希望提速，可使用 T4 GPU，主要加速 Embedding、Docling/MinerU 解析和预审核。A10G 不是普通原型的必需硬件，仅用于 AWS 中国区无法使用 Bedrock 时，在 EC2 上自建 `GLM-4.7-Flash` 的 vLLM/OpenAI-compatible LLM 服务。CPU/T4 方案仍可连接其他区域 Bedrock 或外部 OpenAI-compatible 端点。

## 2. 安装与配置

### 2.1 克隆与依赖同步

```bash
git clone <repo> && cd simple_rag
# 一键安装全部依赖（推荐）：自动检测 NVIDIA GPU，并选择互斥的 CPU/GPU 运行时
# 普通包默认走清华镜像；PyTorch 锁定到官方 CPU/cu126 索引
python setup_env.py
# 无系统 Python时：uv run --no-project python setup_env.py
# 强制 CPU：python setup_env.py --device cpu
# 强制 GPU：python setup_env.py --device gpu

# 也可显式同步最小 Web 运行时：
uv sync --package rag-server --extra cpu
# uv sync --package rag-server --extra gpu
```

> **CPU/GPU 说明**：CPU 模式安装 `fastembed + onnxruntime + faiss-cpu + PyTorch CPU`。NVIDIA GPU 模式安装
> `fastembed-gpu + onnxruntime-gpu + PyTorch cu126`；Linux 同时使用 `faiss-gpu`，Windows 因没有 Faiss GPU wheel，
> embedding 使用 GPU、Faiss 保持 CPU。验证：
> `.venv/bin/python -c "import torch,faiss,onnxruntime as o; print(torch.cuda.is_available(), faiss.get_num_gpus(), o.get_available_providers())"`

### 2.2 配置 .env（LLM / 环境变量）

项目根目录已有 `.env` 示例。关键变量：

> ⚠️ `.env` 请使用 **LF 行尾**（Linux/macOS 编辑或 `sed -i 's/\r$//' .env` 转换）。
> Windows 编辑产生的 CRLF 行尾虽被 `main.py`/`start.sh` 兼容（后者会先去除 `\r`），
> 但直接 `source .env` 时会报 `$'\r': command not found` 且 Bearer token 尾带 `\r` 导致请求失败。

```bash
# Bedrock（默认后端）
AWS_BEARER_TOKEN_BEDROCK=****            # 必填（如使用 bedrock 后端）
AWS_REGION=us-east-1

# OpenAI 兼容（本地 GLM / DeepSeek 等，可选）
OPENAI_API_KEY=****
DEEPSEEK_API_KEY=****

# 离线模式（避免 HuggingFace 联网）
HF_HUB_OFFLINE=1
TRANSFORMERS_OFFLINE=1

# 可选覆盖（LLM 后端/模型/区域）
LLM_BACKEND=bedrock                    # 或 openai
LLM_MODEL=zai.glm-4.7-flash
LLM_BASE_URL=                          # OpenAI 兼容后端的 base_url
AWS_REGION=us-east-1
# Embedding：Web 应用的模型名从 config.json 读取；当前 fastembed/ONNX 路径不应用 dtype 改变运行精度，仅 device 可由环境变量覆盖
EMBEDDING_MODEL=BAAI/bge-small-zh-v1.5  # 仅作为直接无参构造 version_diff.Config() 时的模型默认来源
SIMPLE_RAG_EMBEDDING_DTYPE=auto        # 仅记录到底层 Config 默认；当前 fastembed 路径不改变实际精度
SIMPLE_RAG_EMBEDDING_DEVICE=auto       # auto / cpu / cuda / mps；应用路径下优先级高于 config.json 的 embedding.device
```

### 2.3 配置 config.json（运行参数）

`rag_server/config.json` **不入库**，新环境复制示例后修改：

```bash
cp rag_server/config.example.json rag_server/config.json
```

主要字段（详见 `docs/设计文档.md` 第 8 节）：

```jsonc
{
  "llm_profiles": {
    "self_hosted_glm": { "provider": "openai", "model": "...", "base_url": "...", "api_key": "..." },
    "bedrock_glm_flash": { "provider": "bedrock", "model": "zai.glm-4.7-flash", "api_key_env": "AWS_BEARER_TOKEN_BEDROCK" }
  },
  "llm_routing": { "qa": "bedrock_glm_flash", "pre_review": "bedrock_glm_flash", "conflict_detection": "bedrock_glm_flash" },
  "embedding": { "model": "BAAI/bge-small-zh-v1.5", "device": "auto", "dtype": "auto" }, // dtype 为当前配置保留字段，fastembed 路径暂不改变运行精度
  "retrieval": { "top_k": 15, "similarity_threshold": 0.5, "context_radius": 2 },
  "pre_review": {
    "similarity_threshold": 0.8,
    "version_similarity_threshold": 0.9, // 整篇文档达到此相似度时走版本差异对比
    "batch_size": 0,
    "parse_backend": "auto",         // 默认智能路由；也可固定为 pdfplumber / pymupdf / docling / mineru
    "docling_device": "cuda",        // docling 推理设备: auto/cuda/cpu
    "docling_batch_size": 0          // docling 推理 batch: 0=默认4, 16-32 提升 GPU 利用率
  },
  "conflict_detection": { "min_score": 0.7, "min_similarity": 0.5, "max_similarity": 0.95 },
  "judge": { "prompt_file": "", "prompt_template": "" }
}
```

> **解析后端选型**（详见 docs/PDF解析库实测报告.md）：默认 **auto**——扫描件→mineru、无框线表格→docling、普通数字文本→pymupdf；
> 对文本型制度文档如需最稳定的段落切分，可显式固定为 **pdfplumber**；
> **docling** 用于无框线表格/复杂版面场景（表格 TEDS 开源最强，但布局模型偶把标题行插入段落造成碎句）；
> **pymupdf** 快路径（秒级）、**mineru** 中文扫描件 OCR。auto 智能路由：扫描件→mineru、无框线表格→docling、普通→pymupdf。

> **解析质量旁路**：`parse_qa.enabled` 默认 `false`。开启后预审核解析完成后做规则检查和有限的 LLM 质量审查，结果只提示截断、重复、错列、跨页异常等候选，不修改原始解析缓存；质量旁路的 `incomplete` 不等同于跨文档比较组失败。`parse_cleanup`（若当前配置版本提供）是预审核阶段可选的、仅作用于内存解析对象的 LLM 页眉前缀清洗，默认关闭且不写回 `parse_cache`；当前确认入库会重新由 `DocStore` 解析，未复用该清洗后的对象，因此不会自动改变正式入库向量。启用后需要重启加载配置，但仅重置向量不能让清洗结果进入正式知识库，需另行完成代码适配。

> ⚠️ 提示：**切换 `embedding.model`（向量模型）会使已入库文档的向量全部失效**（向量维度/分布改变），必须**重置知识库**（设置页保存时若检测到模型变更会弹窗提醒；保存后请手动"重置知识库"再重新上传文档），否则检索会维度不匹配或结果失真。
>
> **原型阶段配置生效约定**：配置 API 保存后会返回 `restart_required=true`。请重启服务后再验证新配置；修改 embedding 时还必须重置知识库。这样可避免预审核、入库和既有对话会话混用新旧配置。

## 3. 启动服务

### 3.1 一键启动（推荐）

```bash
# Linux / macOS
./start.sh
# Windows
start.bat
```

脚本会：检测 CPU/GPU 并同步对应 extra → 加载 `.env` → 设置离线环境变量 → 使用 workspace `.venv` 启动 Uvicorn。

### 3.2 手动启动

PowerShell：
```powershell
$env:HF_HUB_OFFLINE="1"
$env:TRANSFORMERS_OFFLINE="1"
uv run --project rag_server uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Linux / macOS：
```bash
cd rag_server
export HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1
uv run uvicorn app.main:app --host 0.0.0.0 --port 8000
```

启动后访问：
- 交互式 API 文档：http://localhost:8000/docs

## 4. Web UI 使用流程

### 4.1 上传与预审核
1. 在"上传"页选择文档（PDF / `.docx`，旧版 `.doc` 需先转换为 `.docx`）。
2. 若库中存在**同名不同内容**文档，上传接口会先返回选择：
   - **保留当前版本并保存新版本**（`coexist`）：继续审核新文档，最终确认时用 `keep_current` 保留旧主版本，或用 `new_primary` 切换新版本。
   - **审核后使用新版本**（`new_primary`）：继续审核并默认倾向在确认时切换新版本。
   - 新文档在上传/审核阶段尚未写入正式文档元数据；确认入库时，有旧主版本的新文档先写为 `inactive`，`new_primary` 才切换为同族唯一 `active`/`primary`。旧版本保留且不会自动删除。
   - 旧客户端的 `overwrite` 仍兼容，但不代表删除旧文件；完整 SHA-256 相同的内容会拒绝重复入库。
3. 上传后自动进入预审核，页面通过 SSE 实时显示进度（解析 → 嵌入 → 检索 → 差异 → 判定）。
4. 完成后展示：
   - **跨文档矛盾**（来自 `pre_review`）
   - **版本变更**（若为新版本，来自 `version_compare`）
5. 管理员**确认入库**或**拒绝**。如果任一确定性比较组或跨文档 LLM 判定失败，顶层任务会标记为“预审核未完成”，不能按安全结果确认，需修复后重跑；`parse_qa` 质量旁路失败只标记其自身 `incomplete`，不单独阻止确认。

### 4.2 问答
1. 进入问答页，输入问题。
2. 答案附带来源引用 `[1][2]`；每个引用编号对应下方来源列表中的一条具体证据。来源按文档分组显示，但同一文档可以有多个引用项；若检索内容存在跨文档矛盾，会显示 ⚠️ 冲突提示。
3. 支持多轮对话、历史查看、会话重置/删除。

### 4.3 文档管理
- 文档列表、PDF 预览、页面 PNG 预览、段落文本预览。
- 删除单篇文档；"清空知识库"会删除所有文档与缓存，从 0 开始（谨慎）。

## 5. 命令行 / 脚本化调用

除了 Web，差异引擎可作为纯 Python 库或示例脚本使用。

### 5.1 用示例脚本验证版本差异 + LLM 归纳

```bash
cd version_diff
uv run python examples/verify_version_diff.py <旧版.pdf> <新版.pdf> --model zai.glm-4.7-flash
# 不传路径时默认使用 data/pdf 下的 IT运维管理规范 v1/v2
```

脚本会：解析两版 → `DiffEngine.version_compare` → 用 `ask_once` 把差异归纳成结构化中文摘要，输出写入 `<repo>/temp/verify_version_diff_output.txt`。

## 6. 常见问题排查

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 启动报 `未找到 uv` | 未安装 uv | 按 https://docs.astral.sh/uv/ 安装 |
| 问答返回 503 `LLM 服务不可用` | API Key 未配置 / 后端不可达 | 检查 `.env` 中对应 `api_key_env` 变量；确认 `llm_routing` 指向的 profile 已配 |
| 解析结果为空 / 段落极少 | 上传的是纯图片扫描 PDF（无文本层） | 默认 auto 通常会路由到 MinerU；若探测不准，可显式设置 `parse_backend: "mineru"` 后重启 |
| Embedding 很慢 | 在用 CPU 且文档很大 | 配置 `embedding.device` 为 `cuda`；或复用向量缓存避免重复计算 |
| HuggingFace 联网失败 | 离线环境未设变量 | 设置 `HF_HUB_OFFLINE=1`、`TRANSFORMERS_OFFLINE=1` 并确保模型已缓存 |
| 预审核进度卡住 | 大文档 + CPU embedding | 属正常耗时，观察日志；可在 `config.json` 调低 `pre_review.similarity_threshold` 减少候选 |
| 冲突检测无结果 | 检索段落均来自同一文档 | `detect_conflicts` 仅对**跨文档**段落对生效 |
| mineru 后端报缺依赖 | 未安装 mineru extra | 运行 `python setup_env.py`（含 mineru[pipeline,vlm]）；无 GPU 会自动用 pipeline 模式 |

## 7. 数据目录

默认根：`~/.simple_rag/`（可在 `config.json` 的 `cache.base_dir` 修改）

```
uploads/        上传文件（SHA256 命名）
doc_store/      已入库文档元数据 + 段落 + 向量索引（FAISS 持久化）
parse_cache/    解析结果缓存
vector_cache/   Embedding 向量缓存
page_cache/     PDF 页面 PNG 缓存
review_tasks.json  终态预审核任务状态快照
review_results/    完整且可复用的预审核结果缓存
chat_history/     问答会话历史
logs/             运行日志（默认 `<cache>/log/simple_rag.log`，以实际 cache 配置为准）
```

> 注："清空知识库"会清空文档元数据、段落、向量索引以及解析/向量/页面/预审核缓存；不会删除 `chat_history/`、日志或上传目录中的原始文件。它也不会替代显式删除聊天历史、日志和上传文件。
