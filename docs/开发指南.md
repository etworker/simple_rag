## 2. 运行测试

每个模块**独立** `pytest`（uv workspace 下共用根 `.venv`，需 `uv`）：

```bash
# 推荐先一键装齐全部依赖（含 dev extra）：
#   python scripts/install_system.py   （无 GPU 也会装 CPU 版 torch + 全量 extras）

cd doc_parser   && uv run pytest            # 71 passed
cd llm_chat     && uv run pytest            # 39 passed
cd version_diff && uv run pytest            # 124 passed
cd rag_demo     && uv run pytest            # 69 passed / 5 skipped（GPU/端到端用例）
```

### 环境性失败（与代码无关，无需处理）
- `rag_demo/tests/test_upload_persistence.py`：Windows 临时目录被他进程锁定（`WinError 32 PermissionError`），收集期即失败。
- `version_diff/tests/test_device_utils.py::test_env_var_overrides_config`：宿主进程预置超大环境变量 `ACC_PRODUCT_CONFIG_V3`（>32767 字符），`patch.dict` 清理时触发 Windows 长度限制。

> 这两项是运行环境限制，并非本次改动引入；CI 中若遇可在隔离环境或排除这些用例。

### 关键测试说明
- `version_diff/tests/test_version_compare_integration.py`：**离线集成测试**——mock 掉 LLM 过滤路径 + 真实 bge embedding（fastembed）跑 `version_compare`；`data/pdf` 缺失时自动 skip。
- `version_diff/tests/test_llm_util.py`：`call_llm_json` 重试语义单测（连续失败→成功 / 全失败 / 非 JSON 触发重试）。
- `version_diff/tests/test_device_utils.py`：`embedding_model_kwargs` 的 dtype 断言为**双路兼容**（有 torch 时返回真实 `torch.dtype` 枚举，无 torch 时返回字符串），两种环境下测试均通过。
- 依赖外部 LLM 端点的用例（如 `test_version_filter.py`）在离线环境可能不稳定，建议加 `@pytest.mark.online` 或在无 LLM 时跳过。

## 3. 扩展指南

### 3.1 新增一个 LLM 后端
1. 在 `llm_chat/src/llm_chat/backends/` 新建 `<name>.py`，继承 `BaseHTTPBackend`，实现 `_parse_response(result)` 与 `chat(messages, system_prompt=...)`。
2. 在 `backends/__init__.py` 的 `_BACKENDS` 字典注册（如 `"<name>": <Name>Backend`）。
3. 在 `defaults.py` 增加对应的 `*_DEFAULTS`（region / base_url / api_key_env / max_tokens / timeout / 重试参数）。
4. 调用方通过 `ask_once(..., backend="<name>", model="...")` 使用。

### 3.2 新增 / 覆盖一个提示词
- 内置模板放 `version_diff/src/version_diff/prompts/`，用 `{count}`/`{items}` 占位符，JSON 示例用 `{{`/`}}` 转义，运行时 `.format()`。
- 运行时覆盖：在 `config.json` 设 `judge.prompt_file`（路径，优先级最高）或 `judge.prompt_template`（字符串）。

### 3.3 新增一条预过滤规则（prefilter）
1. 在 `version_diff/src/version_diff/prefilter.py` 写一个谓词函数 `(cand) -> str | None`，返回命中的原因或 `None`。
2. 把它加入 `_PRECLASSIFY_RULES` 列表（顺序即优先级）。
3. 行为与原实现保持等价即可，无需改动 `pre_classify` 主流程。

### 3.4 调整冲突检测参数
- 全局默认在 `rag_demo/config.example.json` 的 `conflict_detection`（min_score / min_similarity / max_similarity）。
- 底层在 `version_diff/conflict.py::detect_conflicts` 的 `cd_config` 参数。

## 4. 代码约定

- **单一序列化来源**：段落/表格一律用 `to_dict()/from_dict()`，禁止在各处手抄 dict 字面量。
- **公共接口鸭子类型**：对外（如 RAG 问答）只暴露 `judge_pairs`、`detect_conflicts`，调用方传 dict，不感知内部 `TextDiffItem`。
- **LLM 调用统一走 `call_llm_json`**：获得重试 + JSON 容错；不要在各处重复 `ask_once` + 正则解析。
- **失败隔离**：单批 LLM 失败应降级（跳过/回退），不阻断整体流程。
- **依赖单向**：禁止下层包反向 import 上层（如 `version_diff` 不得 import `rag_demo`）。
- **导入路径**：生产代码用正式包导入；测试为隔离可用临时 `sys.path` 注入。
- **配置**：新增运行参数优先放进 `ConfigStore.DEFAULT_CONFIG` + `config.example.json`，避免硬编码。
