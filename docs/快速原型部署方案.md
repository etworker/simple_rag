# Simple-RAG 快速原型与 AWS 中国区部署方案

> **部署分档**：快速原型不要求 GPU，单台普通 CPU 机器即可完成文档解析、版本审核和 RAG 问答；需要缩短 Embedding/解析耗时时，可切换到 T4 GPU。A10G 不是普通原型的必选卡，主要用于 AWS 中国区无法使用 Bedrock 时，在 EC2 上自建 `GLM-4.7-Flash` 推理服务。
>
> **状态说明**：本文同时覆盖本地/单机快速原型和 AWS 中国区目标架构；后者不代表当前仓库已经接入 OpenSearch、DynamoDB、Aurora、Keycloak、S3 或 Secrets Manager。当前实现仍使用本地 JSON/FAISS/文件系统，所需云适配工作见第 7 节。
>
> **文档目的**：说明如何按成本和推理需求选择 CPU、T4 或 A10G，并规划如何在 **AWS 中国区** 将已验证的 Simple-RAG 核心能力扩展为可演示的云上原型，覆盖“文档解析 → 版本差异对比 → RAG 问答 → 对话历史 → 用户管理”。
>
> **版本**：v1.1 ｜ **适用范围**：本地/单机快速原型，以及 AWS 中国区（cn-north-1 北京 / cn-northwest-1 宁夏）目标部署｜ **定位**：CPU/T4 原型或单卡 A10G 自建 LLM 原型，均为非生产高并发承载。

## 1. 方案概述

| 项 | 说明 |
| --- | --- |
| 目标 | 用最少时间搭建可演示原型，验证业务效果与技术链路；后续按需要升级到生产方案 |
| 硬件分档 | **CPU-only**：单台普通 CPU 机器即可运行；**T4 GPU**：可选，用于加速 Embedding、Docling/MinerU 等解析；**A10G**：仅在中国区自建 LLM 时使用。按吞吐、解析耗时和 LLM 部署位置选择，不把 A10G 当作普通原型必需品。 |
| 数据面 | **目标：**向量库 / 数据库 / 对话历史 / 用户管理迁移到 AWS 托管服务；当前仓库仍为本地 JSON/FAISS/文件系统 |
| 高可用 | **目标部署：**推理层仍为单点；完成托管服务适配后，数据面再启用 Aurora 多 AZ、OpenSearch 多节点和 DynamoDB 多 AZ |
| 成本定位 | 约 **¥2–3.5 万/月**（详见第 8 节），仅为后续高可用生产部署的一半左右 |
| 数据合规 | 全部资源位于中国区，数据驻留中国，满足数据主权要求 |

**范围**
- ✅ 包含：GPU 推理（vLLM）、向量检索、关系库（用户/业务）、对话历史、用户认证（OIDC）、密钥管理、对象存储、基础监控、对外接入（ALB）。
- ❌ 不含：跨实例高可用、自动弹性伸缩、多模型路由、生产级灰度/蓝绿、全链路追踪（X-Ray 可选）。

## 2. 中国区关键约束与对应设计

| 中国区约束 | 对原型设计的影响 | 本方案的处理 |
| --- | --- | --- |
| **Amazon Bedrock 不可用** | 中国区没有可直接使用的 Bedrock 托管 LLM API | 需要自建 LLM；使用 A10G EC2（如 g5.2xlarge）运行 `GLM-4.7-Flash` 的 vLLM/OpenAI-compatible 服务；CPU/T4 原型可改用外部或其他区域的 OpenAI-compatible/Bedrock 端点 |
| **A10G 的用途** | A10G 主要解决中国区自建 GLM 推理，不是普通 RAG/Embedding 原型的必选硬件 | 将 `rag_server` 的 LLM profile 指向内网 vLLM 服务；Embedding/解析是否同机运行需按显存和吞吐单独评估 |
| **Cognito User Pools 不可用** | 不能用托管用户池 | 自建 **Keycloak**（ECS Fargate）做 OIDC 用户管理 |
| **SageMaker Inference 不支持 g5/A10g** | 不能走 SageMaker 托管端点跑 A10g | GPU 推理走 **EC2 自管 vLLM**（符合本方案） |
| **公开域名需 ICP 备案**；ACM/Route 53 受限 | 对外域名需备案 | 原型可先用 EC2 公网 IP / 临时 ALB；正式对外前完成 ICP 备案 |
| **HuggingFace 访问受限** | 模型权重拉取不便 | 权重先入 **S3 / 模型仓库镜像**，再挂载给推理节点 |

> 结论：CPU-only 或 T4 只需要运行当前应用与解析/Embedding，LLM 可连接可用的外部/其他区域 Bedrock 或 OpenAI-compatible 服务；在中国区若要求 LLM 同域自建，则使用 A10G EC2 + vLLM。Cognito User Pools 和 SageMaker g5/A10G 托管推理仍受限，其余 AWS 服务是否可用需按目标区域和账号实际核验。

## 3.1 当前本地拓扑（已实现）与目标云拓扑（未接入）

当前仓库可运行的是：浏览器 → FastAPI `rag_server` → 本地文件系统/进程内 FAISS `IndexFlatIP` → fastembed/ONNX embedding → 配置的 LLM 后端；预审核运行态主要在进程内存，终态任务/错误状态可写入任务状态快照，但服务重启不能可靠恢复未完成任务；只有完整成功的审核结果才写入按哈希和配置签名复用的 result cache。当前没有 OpenSearch、DynamoDB、Aurora、Keycloak、S3、Secrets Manager、ALB 或 vLLM 适配。

本章其余 AWS 组件、拓扑图和步骤都是目标方案，必须先完成第 7 节适配，不能作为当前部署说明或现成恢复/权限能力。

**快速原型硬件选择（当前可执行边界）**：

| 档位 | 适用场景 | LLM 位置 | 说明 |
| --- | --- | --- | --- |
| 单 CPU 机器 | 最低成本、功能验证、低并发 | Bedrock（可用区域）或外部 OpenAI-compatible 服务 | 当前解析、Embedding、FAISS 和 Web 服务均可运行，耗时较长但不要求 GPU |
| T4 GPU 机器 | 希望缩短 Embedding、Docling/MinerU 解析和预审核耗时 | 仍可使用远端 Bedrock/OpenAI-compatible 服务 | T4 是可选加速资源，不等于自建 GLM LLM；具体实例规格按显存和样本规模选择 |
| A10G GPU 机器 | AWS 中国区需要自建 `GLM-4.7-Flash` | A10G 上运行 vLLM/OpenAI-compatible LLM 服务 | A10G 主要用于 LLM 推理；rag_server、Embedding 和解析是否同机运行需单独评估 |

下表是 AWS 中国区的目标云组件清单，偏向 **A10G + 自建 LLM** 的完整云上原型，不是 CPU/T4 快速原型的最低部署要求。

| 类别 | 服务 | 推荐规格（原型起步） | 数量 | 用途 |
| --- | --- | --- | --- | --- |
| 中国区自建 LLM 推理 | EC2 **g5.2xlarge** | 1× A10G，8 vCPU，32 GiB | 1 | vLLM `GLM-4.7-Flash` + 可选 rag_server |
| 系统盘 | EBS gp3 | 200–500 GiB | 1 | 系统 + 临时文件 |
| 镜像仓库 | ECR | — | 1 | 存 rag_server / vLLM 镜像 |
| 向量库 | **OpenSearch Service** | 2× `m6g.large.search`（或 `r6g.large`），k-NN | 1 域 | 向量检索（多 AZ） |
| 关系数据库 | **Aurora PostgreSQL** | `db.t3.medium` / `db.r5.large`，多 AZ | 1 集群 | 用户 / 业务元数据 |
| 对话历史 | **DynamoDB** | 按需容量，按 `session_id` 分区，TTL | 1 表 | 会话持久化 |
| 用户管理 | **Keycloak on ECS Fargate** | 1–2 任务（Fargate，无 GPU） | 1 服务 | OIDC 认证 |
| 密钥 | **Secrets Manager + KMS** | — | — | 密钥 / 连接串 |
| 缓存（可选） | **ElastiCache Redis** | `cache.r6g.large`（小） | 1 | 热点缓存 |
| 存储 | **S3** | 标准存储 | 1 桶 | 模型权重 / 文档 |
| 网络 | VPC + 公有/私有子网 + NAT + ALB + SG | — | — | 隔离与接入 |
| 监控 | **CloudWatch**（+ 可选 X-Ray） | — | — | 日志 / 指标 / 告警 |

> 说明：向量库与业务库分开（OpenSearch 专做向量检索，Aurora 做关系数据）。若想减少组件，可用 **Aurora + pgvector** 一库兼任向量与业务（牺牲部分向量检索扩展性）。

## 6. 目标部署步骤（完成第 7 节代码适配后执行）

先根据部署档位选择路径：CPU/T4 仅部署 rag_server 并连接可用的 LLM 端点；中国区自建 LLM 路径才启动 A10G EC2 和 vLLM `GLM-4.7-Flash`。以下步骤按完整 AWS 中国区目标方案编写。

1. **开通中国区账号**：使用中国营业执照开通 `aws-cn` 账号（光环新网/西云数据），与全球区隔离。
2. **网络底座**：创建 VPC，至少 2 个 AZ 的私有子网 + 1 个公有子网，配置 NAT Gateway、安全组（按需最小开放）。
3. **构建并推送镜像**：先按第 7 节完成云服务适配，再用 `docker build --build-arg DEVICE=gpu ...` 构建 GPU 运行时镜像并推送至 ECR；CPU 验证镜像省略该参数即可。
4. **启动推理实例（仅中国区自建 LLM 路径）**：启动 1 台 `g5.2xlarge`（预留/按需），挂 gp3 EBS；通过 SSM Session Manager（避免长期开放 22）登录，用 `docker compose` 起 vLLM `GLM-4.7-Flash` 和可选的 rag_server（模型权重从 S3 挂载/预置）。CPU/T4 快速原型不需要这一步，可在单机启动 rag_server 并配置远端 LLM。
5. **创建向量库**：在 OpenSearch Service 建 k-NN 域，配置索引（维度与 embedding 模型一致）。
6. **创建关系库与用户管理**：建 Aurora PostgreSQL 集群；部署 Keycloak（ECS Fargate），其库可复用 Aurora 或独立。
7. **创建对话历史表**：建 DynamoDB 表（主键 `session_id`，TTL 属性自动清理旧会话）。
8. **注入密钥**：将 LLM/向量/DB 端点与凭据写入 Secrets Manager，由 rag_server 启动时拉取（替代本地 `config.json`）。
9. **对外接入**：创建 ALB，目标组指向 EC2 实例的 8000 端口，绑定证书（ACM 或第三方）。
10. **端到端验证**：上传多版本文档 → 触发版本差异对比 → 发起 RAG 问答 → 检查对话历史落 DynamoDB、向量落 OpenSearch、用户经 Keycloak 登录。

## 8. 成本估算（中国区完整 A10G 云方案；估算值以实际账单为准）

> 以下约 ¥2–3.5 万/月的估算对应 OpenSearch/Aurora/DynamoDB/Keycloak 等完整目标云组件和 A10G 自建 LLM，不适用于单 CPU 或 T4 单机快速原型；CPU/T4 原型应按实际主机、模型端点和运行时长单独估算。

| 项 | 月度估算（¥） |
| --- | --- |
| EC2 g5.2xlarge（GPU 主体） | 11,000 – 14,000 |
| Aurora PostgreSQL（小，多 AZ） | 1,500 – 4,000 |
| OpenSearch Service（2× 小节点） | 3,000 – 7,000 |
| DynamoDB（按量，小） | 数百 |
| ElastiCache（可选，小） | 1,500 – 3,000 |
| ALB + NAT + Secrets/KMS + CloudWatch | 1,000 – 2,000 |
| **合计** | **≈ 2.0 – 3.5 万 / 月** |

**降本建议**
- 开发/验证期可**随时停机**（stop 不计算力费），实际支出更低；EBS 停机仍计少量费。
- GPU 实例建议 **预留实例 / 容量预留**，常年运行可省 40–60%。
- 向量库/历史先最小规格，验证后按需升级。

## 9. 高可用与后续扩展

- **目标数据面 HA**：完成第 7 节适配并部署 OpenSearch、Aurora、DynamoDB 后，数据面可利用托管多副本/多 AZ 降低单实例故障丢数据风险；当前本地 JSON/FAISS 实现不具备该能力。
- **推理层为单点**：1 台 g5.2xlarge 故障会导致 RAG 问答短暂停服（数据不丢）。原型演示前确认实例健康，准备手动重启预案即可。
- **如需高并发 / 推理高可用**：后续可加第 2 台 GPU 实例跨 AZ，前置 NLB/ALB 多目标做负载均衡；规模再大时再引入 ECS/EKS 编排与自动伸缩。

## 10. 风险与注意事项

1. **ICP 备案**：对外域名与主体须完成备案；证书可用 ACM（受限）或第三方。
2. **GPU 配额**：只有中国区自建 LLM 路径需要申请 A10G/G5 配额；CPU/T4 快速原型应根据实际 T4 主机可用性单独规划。
3. **模型权重入 S3**：HuggingFace 受限，权重先入 S3 或模型仓库镜像再挂载。
4. **数据安全**：密钥统一走 Secrets Manager + KMS；S3 启用加密与最小权限；VPC 端点减少公网暴露。
5. **推理单点**：原型阶段可接受；演示前确认实例健康，必要时准备手动重启 runbook。
6. **成本监控**：开启 CloudWatch 账单告警，避免遗忘停机产生费用。
