# Simple-RAG 快速原型部署方案（AWS 中国区）

> **文档目的**：面向客户交付。描述如何在 **AWS 中国区** 快速搭建一个**功能完整、可演示**的 Simple-RAG 原型，用于验证"文档解析 → 版本差异对比 → RAG 问答 → 对话历史 → 用户管理"的端到端流程。
>
> **版本**：v1.0 ｜ **适用范围**：AWS 中国区（cn-north-1 北京 / cn-northwest-1 宁夏）｜ **定位**：单卡 GPU 原型、功能完整、推理层单点（非生产高并发承载）。

---

## 1. 方案概述

| 项 | 说明 |
| --- | --- |
| 目标 | 用最少时间搭建可演示原型，验证业务效果与技术链路；后续按需要升级到生产方案 |
| GPU 选型 | **1× g5.2xlarge**（单卡 A10G 24GB，8 vCPU，32 GiB）—— 单卡但内存充足，vLLM + embedding 同机运行稳定 |
| 数据面 | 向量库 / 数据库 / 对话历史 / 用户管理 **全部采用 AWS 托管服务**，功能与生产方案一致 |
| 高可用 | **推理层为单点**（1 台 GPU 实例，无跨实例 HA）；数据面全托管多副本（Aurora 多 AZ、OpenSearch 多节点、DynamoDB 天然多 AZ） |
| 成本定位 | 约 **¥2–3.5 万/月**（详见第 8 节），仅为后续高可用生产部署的一半左右 |
| 数据合规 | 全部资源位于中国区，数据驻留中国，满足数据主权要求 |

**范围**
- ✅ 包含：GPU 推理（vLLM）、向量检索、关系库（用户/业务）、对话历史、用户认证（OIDC）、密钥管理、对象存储、基础监控、对外接入（ALB）。
- ❌ 不含：跨实例高可用、自动弹性伸缩、多模型路由、生产级灰度/蓝绿、全链路追踪（X-Ray 可选）。

---

## 2. 中国区关键约束与对应设计

| 中国区约束 | 对原型设计的影响 | 本方案的处理 |
| --- | --- | --- |
| **Amazon Bedrock 不可用** | 无托管 LLM API | 自建 LLM 推理（vLLM on EC2 g5.2xlarge） |
| **Cognito User Pools 不可用** | 不能用托管用户池 | 自建 **Keycloak**（ECS Fargate）做 OIDC 用户管理 |
| **SageMaker Inference 不支持 g5/A10g** | 不能走 SageMaker 托管端点跑 A10g | GPU 推理走 **EC2 自管 vLLM**（符合本方案） |
| **公开域名需 ICP 备案**；ACM/Route 53 受限 | 对外域名需备案 | 原型可先用 EC2 公网 IP / 临时 ALB；正式对外前完成 ICP 备案 |
| **HuggingFace 访问受限** | 模型权重拉取不便 | 权重先入 **S3 / 模型仓库镜像**，再挂载给推理节点 |

> 结论：除 Bedrock（无）、Cognito User Pools（无）、SageMaker g5 推理（受限）外，本方案涉及的 AWS 服务**在中国区均可用**。

## 4. 资源与配置清单

| 类别 | 服务 | 推荐规格（原型起步） | 数量 | 用途 |
| --- | --- | --- | --- | --- |
| 推理计算 | EC2 **g5.2xlarge** | 1× A10G，8 vCPU，32 GiB | 1 | vLLM + rag_demo |
| 系统盘 | EBS gp3 | 200–500 GiB | 1 | 系统 + 临时文件 |
| 镜像仓库 | ECR | — | 1 | 存 rag_demo / vLLM 镜像 |
| 向量库 | **OpenSearch Service** | 2× `m6g.large.search`（或 `r6g.large`），k-NN | 1 域 | 向量检索（多 AZ） |
| 关系数据库 | **Aurora PostgreSQL** | `db.t3.medium` / `db.r5.large`，多 AZ | 1 集群 | 用户 / 业务元数据 |
| 对话历史 | **DynamoDB** | 按需容量，按 `session_id` 分区，TTL | 1 表 | 会话持久化 |
| 用户管理 | **Keycloak on ECS Fargate** | 1–2 任务（Fargate，无 GPU） | 1 服务 | OIDC 认证 |
| 密钥 | **Secrets Manager + KMS** | — | — | 密钥 / 连接串 |
| 缓存（可选） | **ElastiCache Redis** | `cache.r6g.large`（小） | 1 | 热点缓存 |
| 存储 | **S3** | 标准存储 | 1 桶 | 模型权重 / 文档 |
| 网络 | VPC + 公有/私有子网 + NAT + ALB + SG | — | — | 隔离与接入 |
| 监控 | **CloudWatch**（+ 可选 X-Ray） | — | — | 日志 / 指标 / 告警 |

> 说明：向量库与业务库分开（OpenSearch 专做向量检索，Aurora 做关系数据）。若想减少组件，可用 **Aurora + pgvector** 一库兼任向量与业务（牺牲部分向量检索扩展性）。

## 6. 部署步骤（可操作）

1. **开通中国区账号**：使用中国营业执照开通 `aws-cn` 账号（光环新网/西云数据），与全球区隔离。
2. **网络底座**：创建 VPC，至少 2 个 AZ 的私有子网 + 1 个公有子网，配置 NAT Gateway、安全组（按需最小开放）。
3. **构建并推送镜像**：基于仓库现有 `Dockerfile`（已预置 embedding 模型 `BAAI/bge-small-zh-v1.5`）构建 rag_demo 镜像，推送至 ECR。
4. **启动推理实例**：启动 1 台 `g5.2xlarge`（预留/按需），挂 gp3 EBS；通过 SSM Session Manager（避免长期开放 22）登录，用 `docker compose` 起 rag_demo + vLLM（模型权重从 S3 挂载/预置）。
5. **创建向量库**：在 OpenSearch Service 建 k-NN 域，配置索引（维度与 embedding 模型一致）。
6. **创建关系库与用户管理**：建 Aurora PostgreSQL 集群；部署 Keycloak（ECS Fargate），其库可复用 Aurora 或独立。
7. **创建对话历史表**：建 DynamoDB 表（主键 `session_id`，TTL 属性自动清理旧会话）。
8. **注入密钥**：将 LLM/向量/DB 端点与凭据写入 Secrets Manager，由 rag_demo 启动时拉取（替代本地 `config.json`）。
9. **对外接入**：创建 ALB，目标组指向 EC2 实例的 8000 端口，绑定证书（ACM 或第三方）。
10. **端到端验证**：上传多版本文档 → 触发版本差异对比 → 发起 RAG 问答 → 检查对话历史落 DynamoDB、向量落 OpenSearch、用户经 Keycloak 登录。

## 7. 本仓库代码改造要点

| 模块 | 改造点 |
| --- | --- |
| `llm_chat` | 新增 **vLLM / OpenAI 兼容后端**，base_url 指向本地或内网 vLLM 端点 |
| `vectorstore` | 从本地 faiss 迁移到 **OpenSearch（k-NN）/ Aurora pgvector** 客户端 |

| 鉴权 | 新增 **Keycloak OIDC 中间件**，保护 API 与 UI |

## 8. 成本估算（中国区按需，估算值以实际账单为准）

| 项 | 月度估算（¥） |
| --- | --- |
| EC2 g5.2xlarge（GPU 主体） | 11,000 – 14,000 |
| Aurora PostgreSQL（小，多 AZ） | 1,500 – 4,000 |
| OpenSearch Service（2× 小节点） | 3,000 – 7,000 |
| DynamoDB（按量，小） | 数百 |
| ElastiCache（可选，小） | 1,500 – 3,000 |
| ALB + NAT + Secrets/KMS + CloudWatch | 1,000 – 2,000 |
| **合计** | **≈ 2.0 – 3.5 万 / 月** |

**降本建议**
- 开发/验证期可**随时停机**（stop 不计算力费），实际支出更低；EBS 停机仍计少量费。
- GPU 实例建议 **预留实例 / 容量预留**，常年运行可省 40–60%。
- 向量库/历史先最小规格，验证后按需升级。

## 9. 高可用与后续扩展

- **数据面已具备 HA**：OpenSearch、Aurora、DynamoDB 均为托管多副本/多 AZ，单实例故障不丢数据。
- **推理层为单点**：1 台 g5.2xlarge 故障会导致 RAG 问答短暂停服（数据不丢）。原型演示前确认实例健康，准备手动重启预案即可。
- **如需高并发 / 推理高可用**：后续可加第 2 台 GPU 实例跨 AZ，前置 NLB/ALB 多目标做负载均衡；规模再大时再引入 ECS/EKS 编排与自动伸缩。

## 10. 风险与注意事项

1. **ICP 备案**：对外域名与主体须完成备案；证书可用 ACM（受限）或第三方。
2. **GPU 配额**：G5 在中国区紧俏，提前申请配额 / 容量预留。
3. **模型权重入 S3**：HuggingFace 受限，权重先入 S3 或模型仓库镜像再挂载。
4. **数据安全**：密钥统一走 Secrets Manager + KMS；S3 启用加密与最小权限；VPC 端点减少公网暴露。
5. **推理单点**：原型阶段可接受；演示前确认实例健康，必要时准备手动重启 runbook。
6. **成本监控**：开启 CloudWatch 账单告警，避免遗忘停机产生费用。

## 11. 原型验收标准（建议）

- [ ] 多版本文档上传成功，版本差异对比结果合理（LLM 归纳可用）
- [ ] RAG 问答命中向量库（OpenSearch）并返回可信答案
- [ ] 对话历史正确写入 DynamoDB，可按会话回顾
- [ ] 用户经 Keycloak 登录后可访问，未登录被拦截
- [ ] 全链路在单台 g5.2xlarge 上稳定运行，延迟可接受
- [ ] 成本在 ¥2–3.5 万/月预算内
